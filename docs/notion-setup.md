# Notion 시작 안내

현재 상태: 가져오기용 파일과 API 자동 설정 도구 준비. 실제 Notion 생성·초대·ChatGPT 연결은 미실행.

## 자동 설정 경로

브라우저 제어와 Notion 편집 도구가 있는 세션이라면 로그인·접근 승인을 거친 뒤 그 도구로 설정을 진행할 수 있다. 로컬 전환만으로 이런 도구가 자동 제공되는 것은 아니다.

이 클라우드 세션에서 API로 생성하려면 다음 준비가 필요하다.

1. 사용자 계정으로 Notion 워크스페이스와 비어 있는 `penta J` 페이지를 만든다.
2. Notion의 [통합 관리](https://www.notion.so/profile/integrations)에서 해당 워크스페이스용 내부 통합을 만들고 콘텐츠 읽기·삽입 권한을 부여한다. 대상 페이지의 연결 설정에서 통합을 추가한다. 메뉴 명칭은 현재 화면을 따른다.
3. 토큰은 클라우드 환경 설정의 보안 입력란 `PENTAJ_NOTION_TOKEN`에 입력한다. 채팅·GitHub·셸 명령 인자에 넣지 않는다.
4. 대상 페이지 ID 또는 URL을 환경 변수 `PENTAJ_NOTION_PARENT_PAGE_ID`에 지정한다. 인증과 `api.notion.com` 네트워크 허용이 실제 실행 환경에 적용되었는지 확인한다.
5. 저장소 루트에서 아래 명령을 실행한다.

```sh
python3 scripts/setup_notion.py --dry-run
python3 scripts/setup_notion.py
```

도구는 Python 표준 라이브러리만 사용하며 멤버 5명, 초기 업무 10개, 콘텐츠 템플릿 1개와 주간 회의·운영 규칙 페이지를 만든다. 데이터베이스의 상태·날짜·지표 속성도 설정한다. API 인터페이스 버전은 `2022-06-28`로 고정했다. 실제 API 호환성과 생성 결과는 인증이 준비된 뒤 검증해야 한다.

반복 실행하면 같은 제목의 초기 항목을 재사용하고 기존 값을 덮어쓰지 않는다. 처음에는 빈 페이지만 허용하며, 이후에는 생성 표시가 있는 페이지를 사용한다. 스키마가 달라진 기존 보드는 덮어쓰지 않고 중단한다. 실행 실패 뒤에는 이미 생성된 항목을 확인하고 재실행한다.

이 경로도 워크스페이스 계정 생성·팀원 초대·ChatGPT 앱 연결을 대신하지 않는다. 로컬에서 사용한다면 인증 값을 로컬의 보안 환경에 넣고 같은 명령을 사용한다.

## 로컬 세션 인계

- 저장소: `jungvis/pentaJ`, 브랜치 `main`.
- 기존 체크아웃이 있다면 그 체크아웃을 사용한다. worktree는 별도 요청이 있을 때만 만든다.
- 이 문서와 [운영 초안](workspace-draft.md)을 읽고, 이미 결정된 5명의 별칭·0원 예산·30일 기간·릴스·UGC 역제안·기존 Pro 구독을 다시 묻지 않는다.
- 첫 작업은 실제 Notion 접근 수단 확인과 연결 승인이다. 보드 생성·5명 공유 권한·ChatGPT 연결 검증을 각각 구분한다.
- 현재 파일과 드라이런 검증만으로 실제 Notion 준비가 완료되었다고 보고하지 않는다.

## 1. 공유 공간 만들기

1. 정한 소유자의 Notion 계정으로 새 워크스페이스 또는 공유할 최상위 페이지를 만든다. 이름은 `penta J`로 한다.
2. 추가 예산이 없으므로 무료 옵션을 먼저 확인한다. 5명을 워크스페이스 멤버로 넣는 경우와 소유자 1명·페이지 게스트 4명인 경우의 현재 제한을 가입·공유 화면에서 확인한다. 유료 플랜을 임의로 선택하지 않는다.
3. 게스트 방식을 선택하면 `penta J` 페이지에 다른 4명의 개인 계정을 초대하고, 필요한 하위 페이지와 데이터베이스도 모두 편집 가능한지 확인한다. 게스트는 워크스페이스 전체 멤버와 권한 범위가 다르다.
4. 이 저장소의 [운영 초안](workspace-draft.md)을 참고해 팀 홈에 이번 주 목표, 업무, 콘텐츠, 멤버, 주간 회의, 운영 규칙을 배치한다.

## 2. CSV 가져오기

Notion의 가져오기 메뉴에서 CSV를 선택하고, 아래 파일을 각각 가져온 뒤 팀 홈 아래에 배치한다. 열이 많은 데이터는 데이터베이스의 CSV 가져오기 경로를 사용한다.

| 파일 | 용도 |
| --- | --- |
| [members.csv](../notion-import/members.csv) | 개안·찬·리트리버·당근·업사 명단. 강점·역할·가능 시간은 미정 |
| [tasks.csv](../notion-import/tasks.csv) | 시작에 필요한 준비 업무. 담당자와 날짜는 배정 전 |
| [content.csv](../notion-import/content.csv) | 콘텐츠 보드와 템플릿 행 1개. 실제 게시 실적이 아님 |

가져온 뒤 상태는 선택 또는 상태 속성, 마감·게시 예정일은 날짜 속성으로 맞춘다. 초대한 계정의 담당자를 사람 속성으로 연결할지는 팀 운영 방식에 맞춰 정한다. `미정`을 자동으로 실제 담당자와 연결하지 않는다.

CSV는 초기 데이터다. 사람·관계·권한·보기 설정을 완성하거나 GitHub와 실시간 동기화하지 않는다. 초기 가져오기는 한 번만 수행하고, 재가져오기 전에 중복 행을 확인한다.

## 3. ChatGPT Pro에서 연결 확인

1. 자신의 ChatGPT 설정에서 앱 목록을 열고 Notion 연결이 제공되는지 확인한다. 표시 이름과 제공 여부는 계정·지역·제품 변경에 따라 다를 수 있다.
2. 제공된다면 연결 절차를 진행하고, 만든 `penta J` 공간에 필요한 접근만 허용한다. 비밀번호나 토큰을 채팅 또는 GitHub에 올리지 않는다.
3. 연결 후 실제 접근 범위를 확인한다. 앱 연결이 Notion 페이지 생성·수정이나 자동 갱신을 지원한다고 가정하지 않는다.
4. 다른 팀원의 Notion 권한과 ChatGPT 앱 연결은 각자의 계정에서 확인한다. Pro 구독 하나가 팀 전체의 Pro 권한을 제공하지 않는다.
5. 앱이 없거나 편집 기능이 없다면 우선 ChatGPT에서 초안을 만들고 Notion에 직접 반영하는 방식으로 운영한다. API 연동과 추가 구독은 이번 범위에 포함하지 않는다.

이 Codex 세션에는 Notion 생성·편집 도구가 제공되지 않았다. 따라서 이 안내와 파일 준비만으로 연결이 완료되었다고 볼 수 없다.

## 4. 설정 완료 확인

- 5명이 각자 계정으로 필요한 팀 페이지와 데이터베이스를 열 수 있다.
- 업무 하나에 담당자·완료 기준·마감일을 정하고, 담당자가 상태와 결과 링크를 변경할 수 있다.
- 다른 사람이 같은 변경을 확인하고 검토 의견을 남길 수 있다.
- 콘텐츠 템플릿을 복제하여 첫 실제 기획을 기록한다. 템플릿 행은 실적에 포함하지 않는다.
- ChatGPT 연결이 있다면 팀이 만든 비밀이 아닌 테스트 페이지를 실제로 읽을 수 있는지 확인한다. 읽기 성공과 쓰기 성공을 구분한다.
- 가입·초대 과정에서 추가 유료 결제가 발생하지 않았는지 확인한다.
